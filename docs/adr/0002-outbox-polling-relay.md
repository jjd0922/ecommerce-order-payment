# ADR 0002: Outbox 폴링 릴레이

## 배경

도메인 상태 변경과 이벤트 발행 결과가 서로 어긋나면 안 된다. UseCase 안에서 외부 브로커로 직접 발행하면 데이터베이스 커밋과 브로커 발행이 서로 다른 신뢰성 경계를 갖게 된다.

## 결정

도메인 상태 변경과 같은 데이터베이스 트랜잭션에서 Outbox 이벤트를 저장한다. 폴링 릴레이는 `FOR UPDATE SKIP LOCKED`로 발행 대상 이벤트를 배치 단위로 선점하고, 발행 성공 후 published 상태로 변경한다.

릴레이 대상은 `PENDING`과 `FAILED` 이벤트이다. 발행 실패 시 이벤트는 `FAILED` 상태와 실패 사유, retry count를 남기고 다음 폴링에서 다시 시도한다.

## 결과

- 이벤트 발행은 at-least-once 방식이므로 컨슈머는 반드시 멱등해야 한다.
- 여러 릴레이 인스턴스가 떠도 다른 워커가 선점한 행은 건너뛰므로 중복 처리를 줄일 수 있다.
- 이 프로젝트에서는 Debezium 또는 Kafka Connect 런타임이 필요한 CDC보다 폴링 방식이 운영 구성이 단순하다.
- published 이벤트는 보관 기간 또는 정리 정책이 필요하다. 그렇지 않으면 Outbox 테이블이 계속 커진다.
