# ADR 0004: 멱등성 레코드

## 상태

채택

## 배경

결제 준비 요청은 클라이언트 재시도나 네트워크 장애로 중복 도착할 수 있다. 멱등성은 결제 테이블에만 묶이면 안 된다. 이후 다른 API에서도 같은 재시도 보장이 필요할 수 있기 때문이다.

## 결정

공용 `idempotency_record` 모델을 사용한다. 이 모델은 key, request hash, response body, status, createdAt, expiresAt을 가진다. 같은 key와 같은 hash 요청은 최초 완료 응답을 재현한다. 같은 key와 다른 hash 요청은 충돌로 거절한다.

## 결과

- 멱등성 처리를 결제 도메인 밖에서도 재사용할 수 있다.
- 최초 응답을 저장하므로 도메인 로직을 다시 실행하지 않고 같은 응답을 반환할 수 있다.
- `IN_FLIGHT` 상태는 동시 중복 요청을 거절하거나 대기시키는 정책의 기준점이 된다.
- 레코드는 TTL 정리가 필요하다. 클라이언트 재시도 키를 영구 보관하면 테이블이 계속 커진다.
